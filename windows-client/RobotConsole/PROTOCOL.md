# v8 速度语义补充（8.0-ros-servo）

生产控制先通过 HTTP session 握手，请求/响应含 `control_profile: ros-servo-v8`。
诊断须为 `bridge_version=8.0-ros-servo`，并返回 `motion_capabilities`：linear_speed_mm_s（2–50）、angular_speed_deg_s（1–10）、input_deadband（0–<1）。
不匹配时 Windows 禁止点动；缺少 profile 的旧客户端 session 请求在改变会话前拒绝。

五轴 32 字节 CRC16 控制帧不变：dx/dy/dz 为线速度比例，pitch/yaw 为角速度比例，均 -1000..1000。
客户端先对物理输入应用死区及合成归一化，再分别乘所选平移/姿态速度除以对应协商上限。
机器人按对应有效上限积分。低速不能再乘旧版的 4/2 上限；旧新程序不能混用。
轴顺序仍为 X,Y,Z,RY,RZ。SDK 原生轴定义保持不变。

诊断新增 blocking_code、blocking_reason、fault_source、fault_latched、input_rearm_required；
arm.motion_state、arm.motion_may_be_active、arm.effective_safety_checks。
arm.pose=null 表示反馈不可用；arm.target 只表示已提交目标，不能证明实际移动。
/configuration 只读，/logs/recent 最多 300 条，完整历史位于机器人日志。

以下为已有底层帧及历史说明；速度语义以上述 v8 规则为准。

# 工业平板通信协议 v6

运行版本 `6.0-industrial`。仅接受 v6 网络包；旧 30 字节网络控制包不会降级执行。内部旧结构仅保留为语义模型及单元测试适配器。

## 控制：UDP 9000，20 Hz，32 字节

所有多字节字段均小端。CRC-16/CCITT-FALSE：poly=0x1021、init=0xFFFF、refin/refout=false、xorout=0；`123456789` 校验值 0x29B1。

|偏移|长度|字段|
|---|---:|---|
|0|4|会话 ID，uint32，机器人握手时随机生成|
|4|2|序号，uint16，模 65536 递增|
|6|4|估算机器人单调时钟毫秒，uint32|
|10|1|flags：bit0..1 模式（0待机/1行驶/2作业），bit2急停，bit3激光请求，bit4 UI心跳新鲜，bit5..7必须0|
|11|16|8个 int16：底盘 X/Y/旋转，机械臂 X/Y/Z/俯仰/偏航；范围 -1000..1000|

|28|2|扫描速度×10，uint16|

## 握手与过滤

GET `/diagnostics` 获取当前运行版本、机器人单调时钟和本次启动的操作令牌；POST `/arm/action`，JSON action=`session`、token、udp_port、request_id，返回 session/server_ms/protocol。客户端仅使用往返不超过100ms的样本对齐相对时钟，诊断请求继续校时。这里存在至多约半个 RTT 的时钟估计误差，不是高精度时钟同步。

初始会话必须先收到待机、全部运动轴为零、激光关闭的有效包。UDP地址和端口绑定到握手声明的控制端；当前部署要求桥接/AP或可直达路由，不支持改变源端口的 NAT。新端接管在旧控制包停发至少500ms后允许，并锁存停止；需要显式恢复，不能自动续跑。重复 session 请求的 request_id 保持幂等。

普通包按模运算判断新序号，拒绝重复和乱序；估算时钟年龄须在 -50..200ms，拒绝时间戳倒退。32位时间戳回绕有效。CRC正确且属于当前会话/端点的急停优先于序号与年龄，即使重复也可停止。未知会话或 CRC 错误的包不触发动作，也不喂有效控制看门狗。

接收端每轮最多提取64包，优先急停，其余只处理最新包，避免顺序追赶旧速度目标。连续运动不重传；释放输入持续发送零目标。使能、恢复、记录零位、回零等通过 HTTP 请求/响应和 request_id 幂等处理；不会因超时自动重发运动管理操作。模式、激光请求是持续发送的期望状态，ACK不证明物理执行。

## 回执：UDP，17 字节

`ACK6`(4) + session(4) + seq(2) + 原始timestamp(4) + 状态(1) + CRC(2)。状态1=普通控制接受或管理期间接受中立心跳，2=停止/故障拒绝运动。客户端仅用匹配已发送包的有效回执计算 RTT。ACK 超时率为最近5秒已结算样本中1秒内未确认的比例，包含双向丢包和迟到。

|偏移|长度|字段|
|---|---:|---|
|0|4|ASCII `TLM6`|
|4|4|session|
|8|2|遥测序号|

|18|21|基础状态：seq(2)、电量百分比(1)、控制年龄ms(2)、车身roll/pitch(float32各4)、6关节裕量(uint8各1)、联锁bits(1)、实际激光状态(1)|
|39|24|末端 XYZ(mm)/RPY(度)，6个float32|

有效位：bit0末端位姿、bit1六轴电流、bit2电池电压、bit3磁吸力、bit4车身姿态、bit5电池百分比。不可用的扩展浮点为 NaN，对应有效位清零；不能按0解释。位姿按SDK新鲜反馈，电流读取 `GetArmHighSpdInfoMsgs` 后除以1000转A。未接入的电池/磁吸/车身传感器标为未知。基础状态中的旧电量/车身字段也必须结合有效位解释。

采样线程和遥测发送线程分开；SDK读取卡住时发送线程继续发送心跳，但过期采样改为未知。客户端验证CRC、会话、遥测序号和发送年龄，旧遥测不能伪装成活跃回传。显示帧已发送与实际位姿分开。

## 心跳与停止

- 上行：序号持续推进的合法控制包，机器人250ms未收到即锁存停止。UI调度器另每50ms更新一次租约；250ms不更新时，发送端清空目标，机器人因UI心跳失效停止。
- 下行：ACK与遥测共同监测，缺失约350ms时客户端清空目标并发急停。普通恢复通信不会恢复旧输入。
- 优先停止通道可中断正在等待 SDK 的使能/恢复；管理期间仅允许中立心跳。
- 软件看门狗不能覆盖 Linux、Python、CAN硬件或整机供电失效；本版没有声称已接通硬件刹车。

## 备用链路

`BackupRobotHost / BackupHttpUrl / BackupWebRtcUrl / BackupLocalBindAddress` 为空时不启用。配置后，持续断链约1.5秒尝试另一条路径，新会话使旧包失效，并要求恢复后重新操作。不自动切回主链路，不跨两条链路同时重复运动。UDP端口沿用9000。两条地址必须通过两套独立网络才能称为物理冗余；一个 WAVLINK 两个地址不算冗余。

CRC和会话用于误码、串包和重放隔离，**不是身份认证或加密**。管理HTTP及控制只部署在隔离的机器人局域网；需要跨不可信网络时应额外使用受管理VPN/认证通道。端口：9000/UDP控制及回传，8080/TCP管理，8889/TCP WebRTC信令，8189/UDP媒体，8554/TCP仅机器人回环发布。
