## 已查明并修复的软件缺陷

1. 接收路径全局要求 DLC=8，丢弃官方 CPV 的七字节参数响应和单字节 ACK。
   原始只读 CAN 查询收到 `181#616b7000000046`（DLC=7）。现按 CAN ID 和报文类型校验长度；
   物理关节/位姿八字节报文仍严格校验，错误短帧不能刷新反馈年龄。
2. 首次使能的零速漂移保护曾依赖 `hold_passed`，在首次测试前不生效。
   现在从模式切换前的实际位姿建立基准，首次使能、切换和零速阶段都监测 2 mm / 1°。
   这不是对实际停止效果的保证，电子急停后仍可能下移。
3. 参数查询全部无响应仍允许使能。现在 48 项参数未完整读到有限数值即拒绝模式切换和使能。
4. 首个故障记录增加实际反馈、漂移和最近 CAN TX 字节；参数快照不再每 50 ms 重复刷盘。
5. ROS 启动拒绝混入激活的 Python 虚拟环境，使用系统解释器；执行器未启动时 CLI 给出明确提示。
6. 发布包漏 SDK `.log/__init__.py`、CHOMP 依赖漏入版本家族，以及旧诊断中错误导入
   `PathSubstitution` 已修正。没有删除保护、写电机 Flash、升级固件或切换到其他运动后端。

## 可用命令

```bash

```
