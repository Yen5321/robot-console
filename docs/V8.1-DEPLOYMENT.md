> **2026-09-17 更新：实机零速保持前发生异常运动，当前保持急停。**
> 下文实机使能/运动步骤为待验证流程，暂不执行。先阅读 `docs/CPV-INCIDENT-20260917.md`。
> 8.1.1 修复不等于实机运动已验证；模拟、纯只读功能仍可用。

本包包含实际 CPV 发送实现。开发电脑完成了软件和虚拟 CAN 测试；随后首次实机使能验证失败，当前不开放运动。

## 1. Windows 上传（旧目录保留）

先退出旧 Windows 控制程序，停止旧桥接和 ROS 进程。新包和旧程序不能同时控制。
在 PowerShell 运行发布目录里的 `deploy-v8.1.ps1`。脚本会上传到
`~/robot-console-v8.1-upload`，安装到 **`/home/tieta/robot-console-v8.1`**，不会启动机械臂。
需要输入 SSH 密码。安装器默认从 `~/robot-console-v8` 导入现场连接配置；若该目录没有本地 YAML，使用下面手动安装方式，从旧桥接导入：

```bash
cd ~/robot-console-v8.1-upload
~/robot-bridge-track-b/.venv/bin/python install_v81.py \
  --archive RobotConsole-v8.1-RobotUpdate.zip \
  --legacy ~/robot-bridge-track-b --target ~/robot-console-v8.1
```

已存在的目标目录不会覆盖；重装请选择新的目录。原 YAML、CAN 名称、网络、相机和零位文件保存在新目录 `config/imported-legacy/`。
新真实零位独立绑定模型，旧零位不会自动加载。安装器输出每项迁移结果。

## 4. CAN 与只读反馈

确认旧桥接、官方演示程序、其他 CAN 控制程序已经退出。工程内锁只能防本工程重复启动，不能排斥其他厂商进程。

```bash
ip -details -statistics link show can0
```

如果仍是 DOWN/STOPPED，并已确认接的是该机械臂的 1 Mbps 总线：

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -details -statistics link show can0
```

先运行 `bash tools/start-ros.sh readonly`，在另一个终端读取
`curl -s http://127.0.0.1:9088/diagnostics | python3 -m json.tool`。
只读入口不发 CAN 查询、使能或运动。核对 SDK 位姿、模型位姿、关节数据持续更新，结束后 Ctrl+C。

## 5. 实机入口：启动仍不使能

暂不启动网络桥接及 Windows 控制，避免调试期间建立不必要的控制会话。
在第二个终端：

```bash
cd ~/robot-console-v8.1

```

确认 `firmware=S-V1.9-0260716`、`node_type=Piper_L_MC`，四类反馈年龄都小于250ms。
等待初次 CPV 参数只读采样结束（最多约24秒；无回复会单独记录，不写 Flash）。

### 5.1 三个代表姿态的 FK 核对

在机械臂受支撑、现场允许的情况下，通过原有现场示教操作取得三个不同的代表姿态。每个姿态稳定后运行一次：

```bash
python3 tools/commission-cpv.py sample-fk
```

每次必须有新鲜反馈，位置差≤5mm、SO(3)姿态差≤2°；关节向量与旧样本差至少0.15rad，避免重复采同一姿态。
不符合会显示具体错误，不能通过 `true/false` 跳过。SDK 模式切换后再次确认现场状态。
样本仅在当前执行器会话有效；重启不恢复运动授权。日志持久保留用于查错。

### 5.2 显式使能与零速保持

```bash
python3 tools/commission-cpv.py enable
python3 tools/commission-cpv.py status
python3 tools/commission-cpv.py hold-test
```

使能和测试命令会要求输入 `RUN`，一次只执行一次。使能须收到六轴使能、CAN=1、CPV=5反馈确认。
保持测试连续五秒发送六轴零速，并测量漂移。超过2mm/1°会阻止继续开放。
软件检测到下移不能保证托住机械臂；**电子急停可能下移，SDK reset 可能掉落**，现场必须具备支撑和停止条件。
本程序不调用 reset，也不自动改用 MOVE L、MIT 或 CPV 位置模式。

### 5.3 十二次有界逐轴测试

按 J1～J6 分别做正、负方向；每次单独运行，现场观察后再运行下一次：

```bash
python3 tools/commission-cpv.py pulse --joint 1 --sign 1
python3 tools/commission-cpv.py pulse --joint 1 --sign -1
```

将 joint 依次换为2～6。目标速度≤0.01rad/s，总非零指令时间含减速≤0.5秒，没有循环执行或无人值守模式。
结果记录实际关节角变化、方向是否一致、其他轴是否漂移；SDK已经反转J2～J5速度，适配层不再反转。
方向/保持失败即停止验证。`status` 显示3个FK样本、保持通过、12个方向结果后，`jog_validated` 才变为true。
这些小幅测试只支持下一阶段低速地面验证，不等同于全行程或额定负载验收。

左右→Y，上下→Z，伸出/收回→X；俯仰/偏航独立。**实机能力上限固定2mm/s、1°/s**，高速未验证。

松手、窗口失焦、切模式和调速均清空输入；正常停止按关节加减速限制降到零，继续零速保持。

## 7. 零位与回零

通过低速验证后，在 Windows “设为零位”记录当前姿态。新文件绑定本版模型，不沿用旧零位。
回零按钮在真实回零测试通过前禁用。先小幅离开零位（≤10mm/3°），停止输入，关闭 Windows并停止桥接；ROS保留运行。
等待停止，再运行：

```bash
python3 tools/verify-home-v81.py
```

这是明确的一次实机运动：输入RUN后显式恢复软件状态、使能，以独立4mm/s、2°/s上限返回刚记录的位置。
超过范围、控制器未恢复、跟随超差或期限失效时拒绝/停止。达到0.5mm/0.2°终点误差才设置本会话回零验证结果。
重新启动桥接和Windows，显式恢复/使能。回零与手动点动互斥，随时可中止；不会自动绕障。
重新记录零位、重启节点后要重新进行回零测试。

## 8. 停止、故障和诊断

- 普通Servo限制：停止/重新按下，不统一升级为SDK急停。
- 控制输入250ms、Servo输出100ms：独立锁存，降速零速，不因新包到来自动续动。
- 实际反馈过期、使能/模式改变、控制器故障、SDK发送失败、手动急停：独立电子停止；不承诺原地保持。
- 软件恢复要求控制器正常、实际关节反馈静止至少500ms；电子急停还需看到真实急停状态及后续恢复状态。不发送 reset。
- 无法确认控制器恢复时：现场支撑并检查/人工复位，界面保持阻止原因；不要关闭保护强开。

```bash
python3 tools/commission-cpv.py status
python3 tools/commission-cpv.py events
python3 tools/collect-diagnostics.py --seconds 10
```

记录位于 `logs/cpv-v8.1.jsonl*`，首次故障、各组物理反馈年龄、收到输入、SDK发送计数、实际位置及零速漂移分开。
`motor_velocity_rad_s` 是电机速度；未验证减速比/符号时，不作为实际关节速度。
正常退出真实执行器时，若已使能会请求电子停止。因此退出前同样需要现场支撑；SIGKILL/掉电无法靠此处理。

## 9. 停止与N100负载验收

先逐轴低速测量松手后的停止时间、剩余位移和姿态变化，目标≤2mm/1°。
另行测试断桥接、暂停Servo、反馈丢失、CAN拔线与执行器进程退出后的控制器行为，不能把软件看门狗当作硬件失联保护。
运行 `python3 tools/observe-load-v81.py --seconds 600`，并让视频、诊断和控制同时运行至少10分钟；记录循环p99/max、各组反馈间隔、`ip -statistics` 的CAN计数与故障日志。
